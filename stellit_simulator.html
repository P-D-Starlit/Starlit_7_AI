Stellit Simulator 가이드

보드에 올리기 전에 PC에서 LED 패턴과 입력 반응을 확인하세요. 타임라인에 버튼과 텍스트 입력을 배치하고, 실행 결과를 프레임 단위로 살펴볼 수 있습니다.

기준 패키지: stellit-win32-x64-1.0.0.vsix · 첫 릴리스 2026-10-23
이 프로그램은 별도의 VSIX 파일로 제공됩니다. Starlit 패키지를 설치하더라도 이 기능을 사용하시려면 VSIX 파일을 별도로 설치하시기 바랍니다.(11월 중 오픈 예정)

주요 기능 설치·첫 실행 타임라인·입력 시나리오 저장 빌드·설정 단축키·문제 해결

GUIDE 01

주요 기능

Starlit 코드를 PC에서 실행하고 재현하기

Stellit은 Starlit 문법을 LLVM 기반으로 다시 구현한 툴체인과 VSCode 확장입니다. 패키지에는 컴파일러 stellitc, 언어 서버 stellit-lsp, 런타임이 포함됩니다. 이 가이드는 확장 이름 Stellit을 시뮬레이터 용도로 사용하는 방법을 설명합니다.

기능확인할 수 있는 내용
장치 미리보기프로필에 따른 LED·LED Matrix·OLED·버튼·직렬 출력
타임라인가상 시계로 실행하고 프레임별 상태 탐색. 같은 입력과 고정 시드는 같은 실행 결과를 재현
입력 스티커버튼 누름과 직렬 텍스트를 원하는 시각에 배치하고 다시 실행
언어 지원문법 강조, 스니펫, 진단, 자동완성, 시그니처 도움말, 호버, 정의·참조 탐색, 문서 개요
빌드·실행PC 실행 파일 생성. GUI 창 또는 터미널에서 실행
프로젝트 설정상태 표시줄에서 장치·플랫폼·아키텍처·HAL·최적화를 고르고 stellit.json에 저장

GUIDE 02

설치·첫 실행

CMD 5×7 예제를 타임라인으로 보기

1. 확장 설치

  1. Windows x64의 Windows 10 1903 이상과 VSCode 1.90 이상을 준비합니다. 제공된 파일은 Windows x64용 패키지입니다.
  2. VSCode에서 Ctrl + Shift + P → Extensions: Install from VSIX...를 실행합니다.
  3. FanMades의 stellit-win32-x64-1.0.0.vsix를 선택하고 필요하면 창을 다시 로드합니다.
  4. 컴파일러·언어 서버·런타임이 들어 있어 Stellit용 별도 툴체인 설치는 필요하지 않습니다. Starlit.exe를 연결하는 F4 설정과는 별개입니다.

2. 소스와 장치 선택

  1. 프로젝트 폴더를 열고 아래 .sl4 예제를 저장해 엽니다.
  2. 오른쪽 아래 언어 모드에서 Stellit 또는 Stellit SL4를 선택합니다. Core 소스 .slc/.shc는 Stellit Core를 사용합니다.
  3. 왼쪽 상태 표시줄의 Device를 클릭하거나 Stellit: Select Device를 실행해 cmd를 고릅니다.
  4. 적용 범위는 이 소스만 또는 이 폴더 전체 중에서 선택합니다. 결과는 stellit.json에 저장됩니다.

5×7 점 이동 예제 · .sl4 다운로드 ↓

아래 예제는 왼쪽 아래에서 시작해 35개 픽셀을 0.1초 간격으로 순회합니다. x=0~4, y=0~6만 사용하며, 매 프레임 이전 점을 지우고 새 위치를 출력합니다.

$import(studio)
$import(matrix)

main:
    img = img88
    img.Clear()
    while 1:
        for y:0:6:
            for x:0:4:
                img.Clear()
                img.Pixel(x, y, 0x002020)
                img.PrintM()
                Delay(100)

3. 미리보기 열기

  1. 편집기 제목 줄의 Open Timeline 또는 명령 팔레트의 Stellit: Open Timeline을 선택합니다.
  2. 편집기 옆 Timeline 패널이 열리면서 자동 컴파일·실행합니다. 장치 선택이 기본이면 상태 표시줄의 cmd를 따릅니다.
  3. 재생 버튼이나 Space로 재생하고, 좌우 화살표로 프레임을 이동합니다. 0.5초 부근에는 다음 행으로 올라간 점을 확인할 수 있습니다.
  4. 소스를 수정해 저장하면 다시 컴파일하며 0 프레임으로 돌아갑니다.
Starlitliter와 StarStarXtension도 .sl4를 사용합니다. 확장을 함께 설치했다면 문서의 언어 모드를 확인하고, 처음에는 단축키 대신 Stellit: Open Timeline / Build and Run 명령을 직접 선택하세요. Stellit 실행은 PC 프로그램 실행이며, StarStarXtension의 F5 업로드와 동작이 다릅니다.

근거: readme.md의 요구 사항·빌드·타임라인 안내와 package.json. 위 예제는 제공된 Stellit 컴파일러로 빌드 및 headless 시나리오 실행을 확인했습니다.

GUIDE 03

타임라인·입력

특정 시각에 버튼과 텍스트를 넣어 반응 확인하기

길이·FPS·장치

새 시나리오는 기본 10초·60 FPS, 총 600프레임입니다. 패널 위쪽에서 길이와 FPS를 조절합니다. 실행당 프레임 상한은 기본 7200이며, 넘으면 조정 사실을 안내합니다.

타임라인의 장치를 기본 이외의 값으로 바꾸면 시나리오의 미리보기 장치만 바뀝니다. 일반 Build / Build and Run의 장치는 상태 표시줄과 stellit.json으로 정합니다. 타임라인은 PC용 headless HAL과 최적화 -O0를 사용합니다.

입력 스티커 배치

  1. 아래 팔레트의 장치 키 또는 text를 타임라인 띠로 끌어 놓습니다. 보통 프레임 시작에 맞추며 Alt를 누르고 놓으면 ms 단위로 배치합니다.
  2. 팔레트를 두 번 누르거나 재생 손잡이의 ＋로 현재 위치에 넣을 수도 있습니다. 띠를 오른쪽 클릭하면 입력 종류를 선택합니다.
  3. 스티커 왼쪽은 종류, 오른쪽은 시각·누르는 시간·텍스트를 수정합니다. 초·ms·프레임 단위를 사용할 수 있습니다.
  4. 스티커를 끌어 위치를 바꾸고, 오른쪽 끝을 끌어 버튼 누름 시간을 바꿉니다. Del 또는 ×로 삭제합니다.
  5. 입력·길이·FPS를 바꾸면 처음부터 다시 실행하지만 재생 위치는 유지합니다. 장치에서 지원하지 않는 키는 빨간 점선으로 표시하고 실행에서 제외합니다.

버튼 입력을 시험하려면

버튼 카운터 예제를 새 소스로 열고 Device=cmd를 선택합니다. 타임라인의 1번·2번 버튼 입력을 서로 다른 시각에 배치하면 직렬 출력의 value 변화를 확인할 수 있습니다. 두 버튼 동시 입력은 예제의 종료 조건입니다. 점 이동 예제는 버튼을 읽지 않으므로 입력을 넣어도 경로가 바뀌지 않습니다.

직렬 입력과 오류 위치

text 스티커에 넣은 내용은 그 시각의 직렬 입력으로 전달됩니다. 프로그램에서 입력을 읽는 코드가 있어야 반응합니다. 런타임 오류는 탐색 막대의 빨간 표시로, 컴파일 오류는 VSCode 문제 창에 표시합니다.

난수 결과 재현

기본 난수 시드는 고정값 1입니다. 같은 코드·입력·시드로 다시 실행하면 같은 프레임을 얻습니다. 설정의 seedMode를 random으로 바꾸면 실행마다 달라지고, 이 시드로 고정으로 현재 시드를 시나리오에 저장할 수 있습니다. 시드는 활성 시나리오 → defaults → VSCode 설정 순으로 우선합니다.

근거: readme.md의 타임라인·시드 안내, package.json의 preview 설정.

GUIDE 04

시나리오 저장

코드와 시험 입력을 함께 보관하기

기본 저장 위치는 소스 옆 <소스 파일명>.scenarios.json입니다. 예를 들어 matrix-scan.sl4에는 matrix-scan.sl4.scenarios.json이 대응합니다. stellit.scenario.storage를 workspace로 바꾸면 VSCode 작업 영역 저장소를 사용합니다.

  1. 타임라인을 열기만 하면 파일이 생기지 않습니다. 첫 편집에서 시나리오 문서가 만들어집니다.
  2. 패널에 ●와 저장 버튼이 보이면 저장하지 않은 변경이 있다는 뜻입니다. 패널에서 Ctrl+S 또는 Stellit: Save Timeline Scenario를 실행합니다.
  3. Ctrl+Z로 되돌리고 Ctrl+Shift+Z 또는 Ctrl+Y로 다시 적용합니다.
  4. Stellit: Open Timeline Scenario as JSON을 실행하면 같은 문서를 JSON으로 편집합니다. 양쪽 변경이 동기화되며 JSON이 잘못되면 마지막 정상 상태를 유지합니다.

패널을 저장하지 않고 닫으면 문서가 배경 JSON 탭으로 남고 저장·버리기·열기 알림이 표시됩니다. 다시 열면 편집 내용이 유지됩니다. 한 파일에 여러 시나리오를 담을 수 있지만 1.0.0의 타임라인은 active 항목만 편집하며, 시나리오 추가·선택 화면은 제공하지 않습니다.

프로젝트와 시나리오의 차이

파일 / 설정보관하는 내용
.sl4 / .slc프로그램 소스
stellit.json빌드 장치·플랫폼·HAL·최적화와 소스별 옵션
.scenarios.json입력 시각·버튼 유지 시간·텍스트·길이·FPS·시드·미리보기 장치
stellit.scenario.storage시나리오 저장 위치 선택. stellit.json으로 정하는 항목은 아님

근거: readme.md와 stellit-scenarios.schema.json. 현재 시나리오 형식은 version 2입니다.

GUIDE 05

빌드·설정

타임라인 밖에서도 PC 프로그램으로 실행하기

Build와 Build and Run

편집기 제목 줄, main 위 CodeLens 또는 명령 팔레트를 사용합니다. Stellit: Build는 빌드, Stellit: Build and Run과 F5는 빌드 후 실행입니다. Ctrl+Shift+B는 VSCode의 빌드 작업 선택을 사용합니다.

결과는 소스와 같은 폴더에 소스 이름의 실행 파일로 생깁니다. Windows에서는 .exe이며, 명령줄과 전체 컴파일러 출력은 Stellit Build 출력 창에 남습니다. 이 빌드·실행은 VSCode 작업으로 진행되며 디버그 세션을 열지 않습니다.

상태 표시줄의 다섯 설정

설정사용법 / 기본값
Devicehighend / cmd / cmdplus. 기본 highend
Platform패키지에서 링크 가능한 OS. 제공된 Windows 패키지는 windows
Architecture선택한 플랫폼에서 가능한 아키텍처. 제공 패키지는 x86_64
HAL출력·입력 방식. 기본 gui
Optimizationdebug(-O0 -g) 또는 release(-O2 -g0). 기본 debug

항목을 누르고 적용 범위를 고르면 stellit.json에 저장합니다. 툴팁에는 실제 명령줄과 값의 출처를 표시합니다. 소스별 설정은 폴더 기본값보다 우선합니다. 여러 stellit.json의 같은 값이 겹치면 작업 영역 상위에 가까운 파일이 우선하고 경고로 안내합니다.

HAL 고르기

HAL화면과 용도
gui별도 창에 장치 화면. 키보드·마우스로 입력
tty같은 터미널에 장치 그림과 직렬 창
console직렬 입력·출력을 표준 입출력으로 연결
headless가상 시계·입력 시나리오·이벤트·프레임 스트림. 타임라인에 사용
publish별도 뷰어에 화면 전송하는 고급 실행 방식

GUI에서는 장치의 화면 버튼을 누르거나 키보드를 사용할 수 있습니다. CMD의 두 버튼은 1·2에 대응합니다. Tab은 직렬 입력 모드, q(버튼 모드)·Esc·창 닫기는 종료에 사용합니다. 타임라인 패널의 Space·화살표는 프레임 탐색용이며 별도 GUI 창의 입력과 구분하세요.

언어 지원과 설정

SL4 문법 .sl4/.sh4는 stellit, Core 문법 .slc/.shc는 stellit-core 언어 모드입니다. main, if, for, while, import 등의 스니펫과 언어 서버의 진단·정의·참조 탐색을 제공합니다. .sl7/.st7 AI 생성과 .stm 실행은 이 확장의 대상이 아닙니다.

언어 서버는 기본 활성화됩니다. 라이브러리 진단은 기본으로 오류만 표시하며 warning·note 또는 CW 그룹별로 켤 수 있습니다. 편집기에서 숨긴 항목도 Stellit Build에는 전체 출력이 남습니다.

근거: readme.md, package.json의 명령·설정·작업 정의와 changelog.md.

1.0.0에서 알아둘 범위

  • 실제 보드 업로드와 중단점 디버거는 제공하지 않습니다.
  • 제공된 win32-x64 VSIX는 Windows x86_64 실행 파일만 링크합니다. 원격 SSH에서는 작업 영역 쪽에서 실행되므로 원격 OS에 맞는 패키지가 필요합니다.
  • 타임라인은 실행이 30초 안에 끝나지 않으면 중단하며, call 파일 저장소는 실행마다 빈 상태에서 시작합니다.
  • 활성 시나리오 하나를 편집합니다. mini·sterm 장치 등 예정 프로필은 지원 대상으로 안내하지 않습니다.
  • Starlit과 다른 동작은 호환 진단(CW 번호)으로 알려 줍니다. 실물 보드 배포 전에는 해당 진단과 실제 동작도 확인하세요.
